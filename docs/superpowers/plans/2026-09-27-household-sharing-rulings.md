# Household sharing — rulings made during the build

Every decision the build controller took on the owner's behalf, in order, with what it costs if wrong. Collected from the build ledger before it was deleted.

- Ruling: T3 harness mechanism left to implementer (setup file vs env-gated project) — spec says whole suite is the test but default npm test must stay meaningful — cost if wrong: harness only runs on demand, completeness regressions slip.
- Ruling: O1 capture flush = per-transaction session in createDatabase().transaction, flushed before COMMIT — keeps change-set durable with rows (spec §6.3) — cost if wrong: nested/non-tx writes miss capture; harness catches it.

- Ruling: O3 Share refuses a book whose base_currency differs from owner's workspace base currency, same sentence as §8.2 — cross-currency books already dropped — cost if wrong: some owners cannot share a secondary-currency workspace until cross-currency lands.
- Ruling: O4 add category_need entity (Op.id = category_account_id, field need, category scope) — otherwise phones disagree on needs/wants — cost if wrong: one extra entity.
- Ruling: O5 convert.ts voiding a purchase when it becomes an investment buy propagates as a void to all devices; accept + document — the purchase leaves the book on the converter's side too — cost if wrong: other member sees purchase vanish.
- Ruling: duplicate append = 200 {seq} of the original, seen becomes Map<deviceId:hlc, seq>; 409 reserved for rotation conflict — distinguishable, idempotent, relay can match — cost if wrong: small relay storage growth.
- Ruling: HLC receive = standard HLC (adopt remote counter when its ms is ahead; max counter when equal); counter overflow bumps ms — correctness of LWW — cost if wrong: none known.
- Ruling: minor 6 (Buffer in seal.ts) upgraded into fix round — breaks in WebView at Task 7 — cost: none.

- Ruling: no-nonce replay within 5 min accepted — spec §9.1 defines timestamp window only; appends dedupe on (deviceId,hlc), claim is one-shot, deletes idempotent — cost if wrong: an observer on the wire could re-send a removal/owners call within 5 min (TLS in production makes this moot).
- Ruling (for T4): natural-key entities (bill_skip, category_need, book_income_override, and any Op.id not a uuid) — an upsert whose hlc beats the tombstone's hlc revives the row and clears the tombstone; uuid entities keep tombstone-wins (spec rule 3) — re-creating a skip/need/override is a normal user act, uuid rows are never re-created with the same id — cost if wrong: concurrent delete+recreate of a natural key resolves by clock, not delete-wins.
- Ruling (for T4): existence-only entities — an upsert with empty fields inserts when the row is absent (and it beats any tombstone); the "winners empty → continue" rule applies only to rows that exist — cost: none.
- Ruling (for T5): outbox stores plaintext change-sets; seal+sign at drain time, not at capture — local DB is plaintext already so nothing leaks, a locked keychain never blocks a save, and a rotation between capture and drain seals under the newer key — cost if wrong: capture/drain interface changes in T5.
- Ruling (for T4/T5): bootstrap ensureCategoryKeys / ensureDefaultCategorySets skip books that have a shared_books row (joined or shared) — keyed/default categories arrive by sync; avoids duplicates under fresh ids — category-set membership is not synced (dropped per spec §0) — cost if wrong: a joiner missing a keyed category until the owner's arrives.
